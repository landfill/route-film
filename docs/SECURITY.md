# 로컬 실행의 보안·안정성

이 문서는 2026-10-24(KST) 보안 리뷰 수정의 설정, 검증 범위와 한계를 설명한다. Route Film의 기본 바인딩은 `127.0.0.1`이며 한 사람이 사용하는 로컬 도구다. 호스트 검사는 DNS 리바인딩 방어이며 사용자 인증이 아니다. 사용자 계정·소유권별 작업 격리는 이번 수정에 추가하지 않았다.

## 요청 호스트와 프록시

- `HOST`는 듣는 인터페이스다. `0.0.0.0` 또는 `::`를 지정해도 모든 요청 호스트가 허용되지는 않는다.
- 기본 요청 허용 호스트는 `localhost`, `127.0.0.1`, IPv6 루프백 `::1`이다. 호스트 형식, 중복 헤더, 명시적 허용 여부를 모든 GET·HEAD·POST 및 다운로드 전에 검사한다.
- 추가 호스트는 `ALLOWED_HOSTS`에 쉼표로 구분한다. ASCII 호스트 이름 또는 IP만 사용하며 스킴·포트·와일드카드는 넣지 않는다.
- 기본 브라우저 출처는 실제 수신 포트의 HTTP 루프백 출처다. 프록시를 사용하면 `ALLOWED_ORIGINS`에 정확한 출처를 별도로 명시한다. Origin이 있는 요청은 허용된 출처이면서 요청 Host와도 일치해야 한다.
- `X-Forwarded-Host`, `X-Forwarded-Proto` 등은 허용 여부를 결정하지 않는다. 프록시는 원래 Host를 유지해야 한다.

설정 형식의 예시는 다음과 같다. 이 설정만으로 공개 운영을 승인하거나 인증을 추가하는 것은 아니다.

```dotenv
HOST=127.0.0.1
PORT=3000
ALLOWED_HOSTS=atlas.example.com
ALLOWED_ORIGINS=https://atlas.example.com
```

테스트는 로컬 HTTP 연결에 악성 Host·같은 악성 Origin·다른 Origin·잘못된 헤더를 보내 거부됨을 확인한다. 실제 브라우저의 DNS 변경, 로컬 네트워크 접근 허가, DNS 캐시까지 포함한 공격 체인을 재현한 것은 아니다.

## 실행 제한과 취소

영상과 단독 포스터는 같은 작업 큐를 사용한다. `RENDER_CONCURRENCY`는 동시에 실행할 무거운 작업 수(기본 1, 범위 1–4), `RENDER_QUEUE_LIMIT`은 초기화 중·대기 중·실행 중을 합친 예약 수(기본 3, 최대 20)다. 전체 예약 한도는 동시 실행 수 이상이어야 한다. 요청은 비동기 파일 초기화 전에 슬롯을 예약하므로 여러 탭의 동시 요청도 같은 한도를 적용받는다. 포화 시 HTTP 429와 `Retry-After: 3`을 반환한다.

영상은 취소 API를 사용한다. 포스터는 응답 완료 전 연결이 끊기면 대기열에서 제거하거나 실행 중 작업에 취소를 전달한다. Sharp의 이미 시작된 네이티브 이미지 작업은 현재 단계가 끝난 뒤 취소를 확인한다. Chromium은 실행 후 사용할 수 있게 되는 즉시 취소를 확인하고 닫는다. 작업 슬롯은 무거운 작업이 정리된 뒤 반환한다. 정상 응답 종료는 취소로 취급하지 않는다.

오디오 합성은 동일한 PCM 수식을 사용하고 8,192 샘플마다 이벤트 루프에 제어를 반환한다. 진행률 요청과 취소를 처리할 수 있으며 기존 구현의 고정 샘플 SHA-256과 일치함을 검사한다.

## 파일·장애·보존

- 상태는 임시 JSON을 쓴 뒤 rename한다. 초기 저장 실패는 안전한 500 응답, 실행 중 저장 실패는 실패 상태로 처리한다. 최종 상태 저장 실패도 무시된 Promise 거부로 서버를 종료시키지 않는다.
- 완성된 영상·포스터·아틀라스·여행 JSON은 자동 삭제하지 않는다. 최종 상태 저장만 실패한 경우에도 현재 실행의 상세 조회와 UI는 이미 생성된 결과를 보존한다.
- 영상·PNG·PDF는 `.partial` 파일을 완성한 뒤 최종 이름으로 바꾼다. 완료·취소·실패 시 새 작업의 `score.wav`, 알려진 `.partial` 파일과 임시 상태 JSON을 정리한다. WAV 정리 전에 FFmpeg 종료를 기다린다.
- 정상 종료 시 진행 중 작업에 취소를 전달하고 정리를 기다린다. 프로세스 강제 종료·시스템 장애·저장 장치 고장 뒤에는 중간 파일이 남을 수 있다. 이전 버전의 파일과 강제 종료 잔여물을 자동으로 일괄 삭제하지 않는다. 실행 중인 서버와 렌더러가 없음을 확인하고 백업한 뒤 필요한 작업 디렉터리만 수동 정리한다.
- 실제 쓰기가 불가능한 동안 새 상태를 영속 저장할 수는 없다. 초기 저장에 실패한 기록은 재시작 뒤 없을 수 있고, 중간·최종 저장에 실패한 기록은 마지막으로 저장된 상태부터 복구된다. 파일 보존과 현재 서버의 생존을 영속 저장 성공으로 표현하지 않는다.

격리된 임시 디렉터리에서 초기·중간·최종 메타데이터 저장 실패를 각각 주입해 서버 생존, 슬롯 회수, 완성 파일 보존을 검사한다. 실제 여행 데이터와 완성 파일에 장애를 주입하지 않는다.

## 오류·조회·브라우저

검증 실패는 4xx, 내부 실행·파일 시스템 실패는 5xx로 구분한다. Chromium이 없거나 실행할 수 없으면 설치 및 `CHROMIUM_PATH` 안내와 503을 반환한다. 응답에는 내부 경로·스택·FFmpeg 진단을 포함하지 않는다. 내부 로그에는 오류 분류와 제한된 오류 코드만 기록한다.

작업 목록에는 요약만 포함하고 여행 전체·좌표·메모·콘티를 넣지 않는다. 같은 입력으로 재시도하기 위한 여행 사본은 상세 API에서 조회한다. 파일 다운로드와 상세 조회도 같은 호스트 방어를 적용받는다. 이는 사용자별 접근 권한 격리를 구현한 것은 아니다.

폴링은 영구적인 4xx에서 중단한다. 408·429·네트워크 실패·5xx는 최대 5회 실패까지 재시도하며, 지수 백오프와 Retry-After 중 긴 대기를 따른다. 최초 오류와 최종 중단 때만 안내하고 수동 상태 재조회 버튼을 제공한다. 작업 변경 시 타이머와 요청을 취소하고, 취소를 무시한 전송 계층의 늦은 응답도 세대 번호로 무시한다.

유효하지 않은 편집 초안과 마지막 유효본이 있으면 초안은 보존하고 미리보기에는 유효본을 쓴다. 둘 다 손상되면 편집기와 미리보기를 함께 샘플로 복구한다. JSON seed는 제공되는 경우 정수 number만 허용한다. 숫자 문자열, 빈 문자열, 불리언, null, 배열과 객체는 거부한다.

SVG ID 치환은 속성에 한정하여 일반 텍스트의 `url(#...)`를 보존한다. 오프라인 HTML은 esbuild로 브라우저 모듈과 import 의존성까지 묶으며, 외부 요청 없이 실행되는지 검사한다.

## 공개 서비스에 남은 조건

이 변경은 외부 배포를 수행하지 않는다. Vercel·Cloudflare 등에서 공개 운영하려면 사용자 인증, 작업·결과 파일의 소유권 검사, 사용자별 연산·저장 할당량, 전송 구간 보호와 배포 환경의 영속 저장을 별도로 설계해야 한다. 네트워크 인터페이스를 열거나 허용 도메인만 추가하는 것으로 이러한 조건이 충족되지 않는다.
